## Этап 9. CI/CD из GitLab в кластер

Перепиши `.gitlab-ci.yml`: сборка образа, пуш в registry, деплой в кластер. Сначала прямой `kubectl apply` из пайплайна с kubeconfig в CI-переменных. Потом перепиши манифесты на Helm-чарт и деплой через `helm upgrade --install`.

**Приёмка:**

- пуш в `main` собирает образ и сам выкатывает его в кластер
- теги образа, число реплик и env вынесены в `values.yaml`, не зашиты в шаблоны
- объяснить, чем `helm upgrade` удобнее голого `kubectl apply` для версионирования релизов и откатов

Комманда:

```shell
kubectl apply 
```

приводит отдельные Kubernetes-ресурсы к состоянию, описанному в YAML, но сам по себе не объединяет их в версионируемый релиз приложения.

Helm рассматривает набор Kubernetes-ресурсов как единый release и сохраняет историю его обновлений.

Историю можно посмотреть командой:

```bash
helm history devops-app
```

При необходимости можно откатить весь release к предыдущей ревизии:

```bash
helm rollback devops-app <revision>
```

Кроме того, Helm позволяет отделить структуру Kubernetes-ресурсов от конфигурации. Шаблоны остаются общими, а изменяемые параметры хранятся в values.yaml.

Поэтому Helm удобнее для:

- версионирования релизов;
- отката приложения;
- параметризации конфигурации;
- повторного использования одних и тех же шаблонов;
- управления всем набором ресурсов приложения как единым release.
